# Freeflow

Freeflow is an MIT-licensed Flutter workbench that runs on your computer. Create, import or clone a Flutter project, edit its Dart code or use the widget tree, and preview the running app in a phone, tablet or desktop viewport. Use the built-in Agent with your own model provider or connect an AI client over MCP.

## Start

1. Install [Rust](https://rustup.rs/) and [Git](https://git-scm.com/downloads). On Windows, install the C++ build tools when Rust setup prompts you.
2. Run **rustup target add wasm32-unknown-unknown** once to enable the browser build.
3. On Windows, double-click **Start-Freeflow.cmd**. On macOS or Linux, run **cargo run --locked -p freeflow-build** in this folder.
4. Select **Try the sample** to run Daymark, or select **New project** or **Import project**.

The workbench opens at [http://127.0.0.1:4747](http://127.0.0.1:4747). Freeflow runs a native Rust server and a Rust browser interface compiled to WebAssembly. Apps are standard Flutter projects in Dart. Use **Settings → Install managed SDK** if Flutter is missing, or point Freeflow at an existing [Flutter SDK](https://docs.flutter.dev/install).

### Flutter updates

Freeflow checks the official stable release feed at startup and periodically while it is running. **Install managed SDK** downloads the matching archive, verifies its SHA-256 checksum and activates it. Future managed SDK updates are automatic by default. Existing SDKs on PATH can be used immediately. Freeflow reports available stable updates for those SDKs and keeps its managed installation separate. **Use cached Dart packages offline** is useful when dependencies are already in the pub cache.

## Build an app

- **Design** shows the real Flutter web app. In **Widgets → Rendered**, inspect live Flutter instances such as rows created by builders and widgets shown by runtime conditions. Select a row to highlight it and open its Dart properties. An edit to a shared constructor applies to all its instances. Use **Widgets → Source** for the constructor tree of a Dart file. Drag a widget to reorder it, move it beside a widget in another list, or place it inside an available child slot. Use the cursor button to pick widgets directly in a compatible debug preview.
- **Simplified** hides recognized single-child layout wrappers so the underlying widgets are easier to find. **Detailed** shows the full indexed tree. The setting works in both Source and Rendered and is remembered in the browser. A selected wrapper stays visible while you edit it. Dragging a simplified tree item moves its hidden wrappers with it. In Properties, use **Modifiers** to switch between the widget and its surrounding wrappers, including supported project widgets with a direct `child` argument. A wrapper with multiple children remains a separate tree item.
- Project widget classes are recognized through local imports, exports and part files, including prefixed imports and named constructors. Component instances and build roots use a purple diamond. Use **See definition** and **See references** in Properties or the widget context menu to navigate between a component and its uses. The Dart SDK resolves up to 200 project references, including constructor and type references. Select a result to open its source widget or Dart code; **Previous** and **Next** in Properties step through the results. Saved source revisions protect navigation after files change.
- Search widget properties by name, type or value. Edit supported values visually, or select **Dart** beside a property to edit its full expression, conditional or callback in place. **Add property** suggests named parameters from the selected constructor using your Dart SDK, including custom widgets defined in the file. You can also enter a property name directly. Use a dotted name such as **style.letterSpacing** to edit a value inside an explicit constructor. **Check Dart** checks the proposed change without saving it. **Reset** removes a named argument; optional properties then use their constructor's default. Changes join the project's Undo history.
- Choose **Add property** or **Edit value** to configure a named parameter using its Dart type. Available editors include text, numbers, booleans, hex colors with alpha, accessible enum members and icons from the selected Flutter SDK. Lists, maps, sets and explicit calls have editable rows. Use **Edit value** inside a row to open a nested value, then **Apply item** to return to its parent. **Dart expression** edits the full value. Freeflow checks the resulting Dart file and saves the whole property as one Undo edit.
- Use **Change constructor** in Properties to choose another constructor of the same Dart class. Freeflow carries over matching values and lets you assign an existing argument to a different parameter. Review any values that will be removed, including child widgets. **Check Dart** previews diagnostics before saving. The switch, any added Flutter import, and changes to enclosing `const` expressions form one Undo edit.
- **Assets** organizes images, audio, videos, TTF/OTF fonts and documents. Upload several files or drag them into the panel, then search by filename or font family. Each file can be up to 10 MiB. Freeflow stores uploads under category folders in **assets/** and updates **pubspec.yaml**, preserving existing entries and comments. Use **Register in Flutter** beside an existing unregistered asset to add its declaration. Fonts receive a family name shown in Assets. Open images, SVG files, audio and videos to preview them, or download the original file. The **Assets** button beside an **Image.asset** path or a **Text** widget's **fontFamily** selects a registered bitmap image or font family. Deleting an asset removes its individual declaration; shared directory declarations remain. Uploads and deletions join Undo with their Flutter declarations, so Undo restores both together. Save or discard unsaved pubspec.yaml edits first.
- Add a child or wrap a widget from Properties. **Browse widget library** searches constructors in the selected Flutter SDK, your project's **lib/** sources and resolved dependencies. Filter by **Flutter framework**, **Project** or **Dependencies**, choose a compatible empty child slot or literal children list, and configure required and optional constructor parameters. Existing named constructors are included. Dart supplies resolved parameter types and checks the whole proposed file before insertion. Public widgets receive an import when needed; imports, insertion and removal of enclosing explicit constructor/list **const** markers undo together. **Check Dart** previews diagnostics without saving. Save component code drafts first. Complex parameters accept a Dart expression in the target file's scope.
- Use **Add modifier** in Properties or **Wrap widget** in the tree menu to put an existing widget inside a Flutter, project or dependency constructor. The selected widget fills one compatible child parameter or becomes a member of its children list. Use **Include other constructors** if a project or package wrapper has an unusual parameter name. Configure the other values and use **Check Dart** to check the result before saving. The original widget, including its comments and callbacks, stays inside the wrapper. The wrapper and any new import undo together. Dart validates types, while Flutter's layout rules still depend on where the wrapper runs.
- The widget library reads saved source and requires the selected Flutter SDK and refreshed dependencies for parameter resolution. Discovery is bounded to 2,000 constructors, 128 project Dart files / 8 MiB and 30 dependency packages from the project or local Pub cache. Each dependency is limited to 192 files / 4 MiB; framework sources to 1,200 files / 32 MiB. Truncated results are marked. Use **Refresh library** after SDK or dependency source changes. Private widgets and constructors are offered only in their defining source file. Arbitrary computed child lists, constructors requiring unresolved generic type arguments and other unsupported patterns can use Code or the Agent. The selected SDK must be able to analyze the imported files; conventional Dart filenames such as **profile_card.dart** avoid analyzer issues with reserved URI characters. If a property uses a Dart conditional, its supported literal branch values remain available in the visual editors.
- Right-click a widget to **Copy**, **Cut**, **Paste** or **Duplicate**, or use the buttons in Properties. With a widget tree row focused, use **Ctrl/Cmd + C/X/V/D**. Copy preserves the complete Dart constructor, including callbacks and expressions, in your system clipboard. Paste fills an available child slot, appends to a literal children list, or inserts after a leaf in a list. Duplicate inserts beside the selected list member. Moving is supported within one Dart file; copying into another file preserves references as written, so add its imports and referenced values as needed. Use the file's save history to restore an earlier version.
- Use **Undo saved edit** and **Redo saved edit** in the top bar to replay saved changes, including assets, visual edits, themes, plans, file saves and Agent changes. A change affecting several files is replayed together. Outside text fields, use **Ctrl/Cmd + Z**, **Ctrl/Cmd + Shift + Z**, or **Ctrl + Y**. Text fields keep their normal Undo behavior. Save or discard drafts in affected files first. A new saved edit clears Redo, and newer changes on disk block replay. This history is kept while Freeflow is running; the per-file save history remains available after restarting.
- **Code** opens project files with Dart highlighting, tabs, formatting and per-file save history. Use **Suggest** or **Ctrl/Cmd + Space** for completions, **F12** for a definition in the project, **Type** for symbol information and **Problems** for live diagnostics in the current Dart file. The Dart SDK checks unsaved code. **Split** shows the preview and editor together. Use **Ctrl/Cmd + S** to save and **Ctrl/Cmd + P** to open files by name.
- **Plan** records your goal, screens and navigation in the project's **FREEFLOW_PLAN.md**. Switch between the screen planner and Markdown. **Plan with Agent** and **Build from plan** prepare prompts for review in the Agent panel.
- **App theme → App settings** edits the seed color, scaffold background and font family in a supported Material theme. **Design values** finds shared top-level and static values across your project's Dart files: colors, text styles, numbers, edge insets, corner radii and font families. Search by name or file and filter by type. Edit supported constructors visually, or enable **Use Dart expression instead** for a complete expression. **Check Dart** checks the proposed change without saving. Existing style fields and surrounding code remain in place; changes join Undo. The list refreshes when saved theme files change. Save or discard a theme file's code draft before editing its values here.
- Use **Theme** beside a widget property to reference a shared **const** design value. For Text, **style → Theme** applies an entire shared text style. **Use design value** is also available in the property's Dart editor. Public values from other project libraries receive an import when needed; existing direct imports and prefixes are reused. The reference and any new import undo together. Private values are offered in their own source file. The syntax index is bounded to 128 Dart files, 8 MiB of source and 500 values; arbitrary dynamic theme patterns can use the code editor or Agent. **App brightness** in Design values controls the compatible running preview's light or dark mode without editing app source.
- **Run** starts a Flutter preview. With Flutter 3.38 or newer, saved Dart changes use **Hot reload** and keep the running app's state. The lightning button applies Hot reload manually. **Hot restart** applies all saved changes and resets the app; use it for changes to `main()`, initializers, or after a rejected reload. A failed Hot reload keeps the running app and shows the error in the console. Removing a Dart library requires Hot restart; restoring the file allows Hot reload again. Older or unrecognized SDKs refresh the page after source edits, with Hot restart available in the toolbar. Changes to assets, web files or dependencies restart the preview. If the Flutter debug server cannot start, Freeflow compiles and serves the web app on a local port. The console shows package, compiler and build output. Use **Refresh Flutter dependencies**, **Analyze** and **Test** from the bottom toolbar.

The preview device controls resize the web viewport. **Expanded** fills the available space without a device frame. Use the preview toolbar to zoom from **30% to 300%**, or use **Ctrl/Cmd + mouse wheel** over a compatible live preview. **Pan mode** lets you drag the preview; press **Escape** to return to the app. **Fit preview** centers it and fits it to the available space. **App brightness** previews System, Light or Dark using the app's theme configuration in a compatible Flutter debug preview. These controls preserve the running app state and do not edit its Dart files. Zoom, viewport and brightness preferences are remembered in your browser.

Use **Run on device** in the bottom bar to launch on a connected phone, running simulator or desktop target detected by Flutter. **Run settings** accepts a Flutter flavor and Dart defines. The device panel shows logs and offers hot reload and hot restart where supported. Launching on iOS requires a Mac with Xcode and signing set up.

Use **Preview on phone** in the preview toolbar to share a QR code and link on your local network. Scan it with a phone on the same network. The mobile browser reloads the web app after a successful rebuild of saved changes. The link stays the same while sharing is active. **Stop sharing** closes the link, and starting again creates a new one. If Windows blocks the connection, allow Freeflow through the firewall on your private network.

## Connect your AI

Open **Agent → Agent settings** and enter your OpenAI-compatible Chat Completions base URL and model name. For a local Ollama server the default base URL is **http://127.0.0.1:11434/v1**. Use a model that supports tool calls for project access and vision for attached images. Enter an API key when your provider requires one. Freeflow stores it in your local data folder.

The Agent streams replies and receives the active file and selected widget as context. **Ask** reads project files. **Edit files** can apply Dart and configuration edits. Use **Restore checkpoint** to undo a set of Agent edits while their file revisions still match.

Project rule files load automatically from **AGENTS.md**, **CLAUDE.md**, **ARCHITECTURE.md** and **.cursorrules**. Root files apply throughout the project; rules in the selected file's ancestor folders provide more specific context. Reading another file also loads its applicable rules. **Agent settings** lists the loaded files and keeps your additional project instructions. Large rule files are shown to the Agent as marked excerpts.

The Agent and connected MCP clients can use **read_project_rules** for an existing or planned file, and **read_app_logs** for the latest preview, device, build, analysis or test output. App logs return up to 200 recent lines with a cursor for later messages. While a compatible debug preview is open in Freeflow, Dart **print**, **debugPrint** and Flutter framework error output are forwarded to its console log. These read tools are available in **Ask** as well as **Edit files**.

Use **read_widget_property** with a widget ID and revision from **inspect_widgets** to read a complete property expression. **edit_widget** supports the **expression** operation to set a Dart expression or remove a named property, including properties beyond the visual catalog. Large values can be edited in the full Dart file instead. The existing MCP connection also exposes **component_definition** and **component_references** for navigation through saved project source using the Dart SDK.

Use **list_assets** in the Agent or existing MCP connection to find app media paths and registered font families. It returns up to 200 results; filter by name or category for larger projects.

Use **list_widget_catalog** in the Agent or existing MCP connection to search saved widget constructors by name, package and category. Ask mode can read the catalog. MCP clients can read **widget_insert_options** for resolved parameters, defaults, child slots and the signature revision, then use **insert_widget** with those revisions and argument values. Insertions receive the same Dart checks and grouped Undo as the visual library.

For wrapping through MCP, look up a constructor with **list_widget_catalog** and use **widget_insert_options** with `operation: "wrap"` and the original widget ID. Pass the chosen slot and other parameter values to **wrap_widget**. The tool fills that slot with the original widget and checks the resulting Dart file before saving.

Use **widget_constructor_options** with the widget ID and source revision to list alternatives. Call it again with the selected constructor suffix and definition revision to get its parameters and existing values. **switch_widget_constructor** saves the Dart-checked change. Set an argument to `{"mode":"keep","value":"child"}` to carry over the old `child` expression, and confirm dropped values with `allowDrop` when needed.

Use **read_design_values** to find saved shared colors, typography and layout values in the Agent or existing MCP connection. It returns up to 200 names, paths, revisions and expression excerpts. Filter by file, type or name when truncated. Ask mode can use this read tool. Values being prepared by the Agent remain in its pending Dart files until the Agent finishes.

Use **reload_preview** to apply saved changes with Hot reload where supported. **restart_preview** explicitly resets the app with saved changes. Both tools start a stopped preview. Read **preview_status** or **job_status** for reload capability, completion and compilation errors; a successful Hot reload increments `reloadCount` while keeping the preview's page `epoch` unchanged.

Open a project and select **AI Connect**. It generates project-scoped setup commands for **Codex**, **Claude Code** and **Claude Desktop**. Your client can edit project files, work with the visual widget tree, and run previews, analysis and builds. The MCP server uses standard STDIO for other local MCP clients as well.

Use **cargo run --locked -p freeflow-build -- --no-open** to run Freeflow without opening a browser. The **AI Connect** dialog generates commands for the native **freeflow mcp** executable. Start Freeflow first and pass the same **--home** to both processes if you use a custom data folder. Existing MCP clients need the updated command from **AI Connect**. Use Codex for ChatGPT-based local development. The [ChatGPT web app's MCP integration](https://help.openai.com/en/articles/12584461) connects to remote servers.

Freeflow has no subscription of its own. Your AI client and backend providers retain their own usage limits.

## Source control

Use **Source control** to initialize Git, connect a remote, inspect and stage changes, commit, switch branches, fetch, pull and push. Use **Clone repository** to open a Flutter repository over HTTPS or SSH. Git uses the credentials and commit identity configured on your computer.

If a pull finds a conflict, open its diff to compare the two versions. Accept either version or edit the file in the code editor and mark it resolved. Commit the merge when all conflicts are resolved.

## Connect a backend

| Provider | What to enter | What Freeflow adds |
| --- | --- | --- |
| Firebase | Web app settings from the Firebase console. Register Android and iOS app IDs for builds on those platforms. | Firebase initialization, Firebase Auth and Firestore packages |
| Supabase | Project URL and publishable or legacy anon key | Supabase Flutter client initialization |

Freeflow templates call **FreeflowBackends.initialize()**. For an imported app, the Backends dialog shows how to add that call before **runApp()**. Add sign-in screens and data queries in Dart. Configure Firebase rules and Supabase row-level security in the respective backend project.

Freeflow passes public client configuration with **--dart-define-from-file**. Find the config path under **Backends → Build outside Freeflow**. Source exports leave this file and Android signing credentials in their local folders. See [Firebase for Flutter](https://firebase.google.com/docs/flutter/setup) and [Supabase for Flutter](https://supabase.com/docs/guides/getting-started/quickstarts/flutter).

## Export and submit

| Target | Output | What you need |
| --- | --- | --- |
| Web | ZIP containing the compiled website | A static host. Set the base path for subfolder hosting. |
| Google Play | Release AAB | Android SDK and JDK, plus an upload key for submission |
| Android device | Debug APK | Android SDK and JDK |
| App Store | Signed IPA | macOS, Xcode, an Apple team and signing configuration |
| Flutter source | ZIP containing the project | A Flutter SDK to continue on another machine |

- **Web**. Open **Export → Web → Publish website**. Save your Netlify team slug and [personal access token](https://docs.netlify.com/api-and-cli-guides/api-guides/get-started-with-api/#personal-access-tokens). Freeflow builds the app locally and creates a site in your team. **Update deployment** replaces the build at the same URL. **Unpublish** disables the site, and **Publish** enables it again after the new build is ready. Use **Refresh status** to check an interrupted upload. The hosting token is saved under the local Freeflow data folder.
- **Google Play**. For the default Kotlin Gradle template, **Configure signing** accepts your upload keystore. Other Gradle layouts can use [Flutter's Android signing instructions](https://docs.flutter.dev/deployment/android#sign-the-app). Upload the first AAB in Play Console. After that, build a signed AAB and use **Upload release build** with your package name, target track and [service account JSON](https://developers.google.com/android-publisher/getting_started). The form defaults to a draft on the internal track.
- **App Store**. Create the app in App Store Connect and set its team and bundle identifier in Xcode. Build the signed IPA on macOS, then use **Upload release build** with your [App Store Connect team key](https://developer.apple.com/help/app-store-connect/get-started/app-store-connect-api/). Apple processes the build before you can distribute it in TestFlight or submit it for review. On Windows, export the Flutter source to continue on a Mac.

For Google Play and App Store exports, use **Build options** to set the app version and build number for that export. Blank fields use the values in pubspec.yaml. Store upload keys are used for the selected upload. Freeflow saves a local receipt after the store accepts the build.

## Development

Run **cargo test --locked** to check the workbench and **cargo run --locked -p freeflow -- --help** for launch options. Use **cargo run --locked -p freeflow-build -- --build-only** to compile the browser assets into **target/freeflow-web**. Freeflow listens on loopback and serves Flutter previews from a separate local origin. Project metadata, file history, the managed SDK and generated builds live under **~/.freeflow** by default. Use **--home** for another location, **--port** to change the workbench port, and **--no-open** for a headless session. Import Flutter projects you trust to run on this computer.

## Current scope

Freeflow 0.1 covers local Flutter development, visual edits for supported Dart constructors, project AI, Git source control, backend setup, exports, Netlify publishing and store build uploads. Hosted collaboration, store review workflows and visual editing of arbitrary dynamic Dart UI are outside this release.

See the dated [Dreamflow comparison and progress baseline](docs/PARITY.md) for individual acceptance criteria, evidence, known gaps and a reproducible progress score. Its [structured data](docs/parity.json) keeps the comparison criteria stable between updates; the score is not a claim of complete product parity.
